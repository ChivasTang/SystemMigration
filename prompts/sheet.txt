- 参考値の UID/GID が使用済みの場合は、未使用の値に変更してよい。
- 変更した場合は、変更前後の値と理由をコメントに残す。

# 採番ルール
- システム用途のユーザ:RHEL 8 の一般ユーザ範囲(1000 以上)を推奨する。
- 参考値が未使用ならそのまま使う。使用済みなら、同じ範囲の次の空き番号を使う。
- 複数ユーザが同じグループ(oinstall)を共有する場合は、グループを 1 回だけ作成する。

# 処理内容
1. グループごとに、グループ名の存在と GID の使用状況を確認する(getent group <グループ名>、getent group <GID>)。
   - グループ名が存在する場合:作成せず、既存 GID を使う。
   - グループ名がなく GID が未使用の場合:参考値の GID で作成する。
   - グループ名がなく GID が使用済みの場合:空き GID を選んで作成する。
2. ユーザごとに、ユーザ名の存在と UID の使用状況を確認する(id <ユーザ名>、getent passwd <UID>)。
   - 存在する場合:作成せず、現状(id、passwd 行)を表示して、定義との差異を報告する。
   - 存在しない場合:UID の重複を確認してから作成する(useradd -u <UID> -g <グループ> -d <ホーム> -m -s <シェル> -c "<コメント>" <ユーザ名>)。
3. ログインシェルが存在することを確認する。/bin/ksh は ksh パッケージが必要。未導入なら dnf install -y ksh を実行する。
4. 作成後、各ユーザに切り替えて profile を確認する。
   - su - <ユーザ名> -c 'id; echo $SHELL; pwd'
   - cat ~/.bash_profile ~/.bashrc(bash の場合)
   - cat ~/.profile(ksh の場合)
   - /etc/skel から配布されたファイルの有無も確認する。
5. パスワードは設定しない。必要な場合は <パスワード> とし、本文に実値を書かない。

# コメント(注釈)の要件
- 各ユーザについて、スクリプトの該当箇所に次の項目をコメントで記載する。
  1. 用途(例:バックアップ用、アプリ実行用、FTP 用)
  2. 権限設定(sudo の有無、ホームディレクトリの権限、umask)
  3. 所属グループ(プライマリ、補助)
  4. 特殊な設定・制限(ログインシェル、ログイン可否、パスワード期限など)
  5. UID/GID を変更した場合の変更前後の値
- 用途や権限が分からないものは推測せず、【要確認】と記載する。
- コメントは日本語で書く。

1. 実行用シェルスクリプト(bash、冪等、root で実行)
   - set -u を使い、各処理の結果(作成/既存/スキップ/エラー)を表示する。
   - 既存ユーザ・グループは変更しない。
