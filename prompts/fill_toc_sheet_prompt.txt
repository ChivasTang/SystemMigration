# 依頼内容
「APサーバ構築手順書」の作業用ファイルについて、目次シートの追加行の要否を確認し、指定シートの空欄のうち埋められるものだけを埋めた Excel を新規作成してください。

# 役割
本プロジェクト（処理用DB老朽化対応／セキュリティ強化）のインフラ・ミドルウェア移行に精通したシステムエンジニアとして作業する。
記載はすべて日本語とする。専門用語・略語は初出時に正式名称または簡単な説明を添える。

# パラメータ（実行前に置き換える）
- 【対象シート】：今回埋めるシート名。複数ある場合は読点で列挙する。未指定のまま実行しない。
  例：EDR、TaniumClient、AWSCLI2、Perl、vsftpd、HULFT
- 【環境】：dev／qa／honban のいずれか。未指定の場合は qa とし、他環境の値は書かない。

# 参照するファイル（この順で読む。存在しないファイルは「参照できなかった」と報告し、推測で補わない）
1. C:\workspace\SystemMigration\instructions.txt
2. C:\workspace\SystemMigration\templates\APサーバ構築手順書_temp_ver1.xlsx（作業元。これを直接上書きしない）
3. C:\workspace\SystemMigration\templates\APサーバ構築手順書_テンプレート_ver1.xlsx（書式・列・凡例の参照用。本文の実値はコピーしない）
4. C:\workspace\SystemMigration\参照資料 配下（存在する場合のみ。デザインシート、現行設定）
5. C:\workspace\SystemMigration\AP 配下の手順書は、シート構成と書式の参考に限る。記載されている製品・バージョン・アプリ名は本プロジェクトの現行仕様として使わない。

# やってよいこと
1. 目次シートを、実在するシートおよび instructions.txt の対象範囲と突き合わせ、追加した方がよい行があれば提案する。
2. 【対象シート】について、空欄（セルが空、または「＜記入＞」のまま）のうち、参照資料で確定できる項目だけを埋める。
3. 埋めた結果を、新しい Excel ファイルとして出力する。

# やってはいけないこと
- 追加行の提案を、了承前に成果物へ反映しない。提案は報告に書くだけとする。
- 作業元ファイル、テンプレート、参照資料を変更しない。
- 資料や公式ドキュメントで確認できない値を、確定事項として書かない。
- 実施結果、判定、実施者、実施日時、承認者、承認日は、実施記録であるため空欄のままにする（「＜記入＞」がある場合も実施時用として残す）。
- パスワード、秘密鍵、アクセスキー、接続文字列の実値は書かず「＜別途管理＞」とする。
- コマンドは、コピーして実行できる形で書く。省略、プロンプト記号（# や $）、未確認のオプションを付けない。確認できないコマンドは書かず「要確認」とする。
- 依頼範囲外の章の新設、列構成の変更、書式の作り直しはしない。

# 目次の追加行（提案のみ）
次を確認し、該当するものだけを提案する。該当しなければ「追加行なし」と書く。
- 目次にあるシート名に対応するシートがブック内にない
- instructions.txt および確定済みの対象（後述）にある作業が、目次にない
- 目次にあるが、今回の対象外と確定している作業

提案は次の表で書く。成果物には行を追加しない。
項番／シート名（案）／内容（案）／追加する理由／参照した資料／要確認かどうか

# 空欄の埋め方
- 埋める対象は【対象シート】だけとする。目次シート自体は、【対象シート】が「目次」のときだけ埋める。
- 目次の「内容」が空の行は、そのシートが何の手順かを1文で書く。対象に含めるか未確定の行は、文末に「（要確認）」と書く。
- 備考は、注記が必要なときだけ書く。注記がなければ「－」とする。
- 手順シートがまだなく、template シートしかない場合は、template シートを複製して【対象シート】のシートを作る。列・区分（事前確認／変更前バックアップ／作業／事後確認／切り戻し）・設定ファイル欄の構成は template を変えない。
- 手順本文は、参照資料で操作・設定値・期待結果が確認できた行だけ書く。1コマンド（1操作）＝1行。行が足りなければ書式と入力規則を保ったまま行を追加し、使わない雛形行は削除する。
- 環境ごとに異なる値は直書きせず、パラメータID（【P-区分-連番】）で参照する。IDの対応表を同じファイルのパラメータ欄に置く。パラメータ欄がない場合は、手順シートの下に「項目／現行値／移行後の値（【環境】）／備考」の表を追加する。
- 現行値と移行後の値が異なるセルは黄色にする。未確定で仮の値を入れたセルはオレンジにし、「要確認」と書く。仮の値を置かない場合は空欄のままにせず「要確認」と書く。
- 該当しない欄は「－」とする。
- 色を使ったファイルには、色の意味（黄＝現行との差分、オレンジ＝仮の値・要確認）を凡例としてシート先頭または末尾に書く。

# 成果物の体裁（仕様書フォーマット）
新規ファイルは、次のシートをこの順で持つ。自由形式のメモや、この構成以外のシートは作らない。
1. 表紙：タイトル、対象シート名、対象環境、バージョン（ver1）、作成日、作成者（＜記入＞）、承認欄（空欄）
2. 変更履歴：バージョン、更新内容、作成者、作成日、確認者、確認日
3. 目次：項番、シート名、内容、実施状況、備考。シート名には当該ファイル内のシートへのリンクを付ける。実施状況は作業を伴わないシートは「－」
4. 本文：【対象シート】の内容。手順なら template の列構成、パラメータなら「項目／現行値／移行後の値／備考」
5. 要確認事項一覧：No.、区分（要確認／仮の値）、該当箇所、内容、仮の値、確認先、状況（未回答）

書式は作業元ファイルに合わせる。見出し、印刷範囲、見出し行の繰り返し、フッター（ファイル名、ページ番号、シート名）を設定する。フォントはＭＳ ゴシックとする。

# ファイル名と保存先
- 保存先：C:\workspace\SystemMigration\templates
- ファイル名：APサーバ構築手順書_temp_【対象シート】_ver1.xlsx
  - 【対象シート】が複数のときは、シートごとに1ファイルとする。1ブックにまとめない。
  - ファイル名に使えない文字（\ / : * ? " < > |）は使わない。シート名にこれらが含まれる場合は、除いた名前にし、表紙に正式なシート名を書く。
- 同名ファイルがある場合は上書きしない。ver2、ver3 と番号を上げて保存する。
- 作業元の APサーバ構築手順書_temp_ver1.xlsx は変更しない。

# 今回の範囲で確定している前提（これに反する資料があれば、合わせずに報告して止める）
- 対象は AP サーバ（RHEL 8.10）。Windows Server 2025 は対象外。
- Java は Amazon Corretto 8。Apache は RHEL 8.10 標準パッケージの 2.4。Tomcat は 9.0.122。
- Tomcat は ap01～ap06 の6インスタンス。war は apc.war、msu.war、mu2.war、mst.war、fmt.war、api.war。
- 標準同梱アプリ（ROOT、docs、examples、manager、host-manager）は削除する。Shutdown ポート、AJP、JMX リモート接続は無効化する。Apache と Tomcat の連携は mod_proxy_http。
- ASTERIA Warp 2406、EDR、Tanium Client、AWS CLI バージョン2、Perl、vsftpd、HULFT は対象に含める。メール中継は対象外。
- JP1、CSH、nkf は移行先に存在する。本手順書の対象に含めるかは要確認とし、追加行の提案にだけ書く。
- Oracle Client の要否は要確認。要否が分かるまで手順本文を書かない。
- DB は Amazon RDS for Oracle 19c。本書に書くのは AP サーバからの接続設定と疎通確認まで。
