# 依頼内容
「APサーバー構築手順書」のテンプレート（ひな形）を新規作成してください。

# 背景と目的
「処理用DB老朽化対応（セキュリティ強化）」プロジェクトでは、AWS 上の RHEL 8.10 サーバーに AP サーバー（Tomcat 9.0.122 + Amazon Corretto 8）を新規構築します。
Tomcat はアプリケーションごとに 1 インスタンス、計 6 インスタンス（ap01～ap06）を起動する構成です。
この構築を dev／qa／honban の 3 環境で同じ品質で実施するため、手順書を作成する予定です。
今回はその前段として、手順書の「型」となるテンプレートだけを作成します。
実際のコマンドや設定値は後続の作業で記入するため、今回は記入しません。

テンプレートの読み手は次の 2 種類です。どちらにとっても迷わず使えることを重視してください。
- 手順書を執筆する人：どの欄に、何を、どの粒度で書くかがテンプレートを見るだけで分かること
- 手順書を見て作業・確認する人：コマンドをコピーして実行し、期待結果と照合し、結果を記録できること

# 成果物
- ファイル名：APサーバー構築手順書_テンプレート_ver1.xlsx
- 形式：Excel（.xlsx）
- 保存先：C:\workspace\SystemMigration\templates
- 同名ファイルが既にある場合は上書きせず、バージョンを上げた別ファイルとして保存してください。
- 記載はすべて日本語にしてください。

# シート構成（案）
次の構成を基本とします。より良い構成があれば、構成案の提示時に理由を添えて提案してください。
1. 表紙：タイトル、バージョン、作成日、作成者、承認欄
2. 改訂履歴：バージョン、改訂日、改訂箇所、改訂内容、改訂者
3. 目次：各シートへのリンク付き
4. 凡例・記入ルール：色の意味、プレースホルダーの書き方、各列の記入方法
5. 作業概要・前提条件：目的、対象サーバー、対象環境、前提条件、実行ユーザーと権限、事前準備物、関連ドキュメント
6. 環境別パラメータ一覧：「項目／現行値／移行後の値（dev／qa／honban の列に分ける）／備考」
7. 構築手順：本体（列構成は後述）
8. 動作確認手順：構築手順と同じ列構成
9. 切り戻し手順：構築手順と同じ列構成
10. 要確認事項一覧：No.、該当シート・該当箇所、内容、仮の値、確認先、期限、状況

# 構築手順シートの列構成
手順No.／大項目／作業内容／対象サーバー／実行ユーザー／コマンド・設定内容／期待結果（確認ポイント）／実施結果（dev／qa／honban それぞれ OK・NG を選択）／実施日時／実施者／確認者／備考

構築手順シートには、次の大項目を見出し行としてあらかじめ入れてください（各見出しの下は空の入力行にします）。
章立ては仮のものなので、過不足があれば構成案の提示時に指摘してください。
- 事前確認
- OS ユーザー・グループ作成
- Java（Amazon Corretto 8）インストール
- Tomcat 9.0.122 インストール
- Tomcat インスタンス作成（ap01～ap06）
- Tomcat 設定
- 標準同梱アプリケーション（ROOT、docs、examples、manager、host-manager）の削除
- 不要機能の無効化（Shutdown ポート、AJP コネクタ、JMX リモート接続）
- 自動起動設定
- war ファイル配置（apc.war、msu.war、mu2.war、mst.war、fmt.war、api.war）
- 起動確認
- Apache 2.4 との連携確認（mod_proxy_http）

# 記載ルール（テンプレートに組み込むもの）
- 色分け：現行と移行後の差分は黄色、仮の値（要確認）はオレンジとし、凡例シートに色見本と意味を記載する。
- 環境ごとに異なる値はコマンド欄に直接書かず、＜ホスト名＞のようなプレースホルダーにして「環境別パラメータ一覧」を参照させる。この方針を記入ルールに明記する。
- コマンド・設定内容の欄は、そのままコピーして実行できる形で省略せずに書く欄であることを記入ルールに明記する。等幅フォントにし、セル内改行でも読みやすい列幅にする。
- パスワード、秘密鍵、アクセスキーなどの機密情報は実値を書かず「＜別途管理＞」と記載するルールを明記する。
- 不明点は推測で埋めず「要確認」と記載し、要確認事項一覧にも転記するルールを明記する。
- 実施結果の列は、入力規則（プルダウン）で OK／NG／対象外 を選べるようにする。
- 印刷しても使えるよう、各シートに印刷範囲、見出し行の固定、ページ番号を設定する。

# テンプレートとしての注意点
- プロジェクト固有の実値（ホスト名、IP アドレス、パス、ポート番号など）は記入せず、＜＞のプレースホルダーにしてください。資料で確認できない値を確定事項のように書かないでください。
- 書き方が伝わるよう、各表に記入例を 1～2 行入れてください。記入例は「記入例（作成時に削除）」と明示し、本文と区別できる書式にしてください。
- 記入例の内容は、製品の公式ドキュメントで確認できる一般的なもの（例：バージョン確認コマンド）に限ってください。

# 進め方

   (2) 内容の要約
   (3) 要確認事項と仮の値の一覧
