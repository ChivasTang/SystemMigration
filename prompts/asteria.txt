現状の APサーバ構築手順書_ASTERIA Warp_ver1.xlsx は手順が【要確認】のままの雛形なので、
InstallGuide.pdf を根拠に ASTERIA Warp 2406（Linux 64bit 版）の新規インストール手順へ置き換えた ver2 を作成する。

# 前提
- 対象：AWS 上の RHEL 8.10。新規インストールとする（旧 ASTERIA 4.5.1 からの上書きバージョンアップは不可：InstallGuide 1.6.1）。
  既存フローの移行（MigrationGuide.pdf の範囲）、フローデザイナー（Windows）、アダプター適用は本書の対象外。
- 製品：ASTERIA Warp 2406、Linux 64bit 版。
- Java：Amazon Corretto 8（Java シートで導入済み。JAVA_HOME=/usr/lib/jvm/java-1.8.0-amazon-corretto.x86_64、/usr/local/jdk）。
  サーバーの実行には 64bit 版 Java 8 が必要（InstallGuide 1.5）。Corretto 8 が 2406 のサポート対象かは製品サポートページで確認し、確認できなければ【要確認】。
- 実行ユーザ：root ではなく ASTERIA 専用の OS ユーザで実行する（InstallGuide 1.4）。
  「ユーザ・グループ」最新版に ASTERIA 用ユーザの定義がないため、仮の値として現行と同じ eaiadm（uid 400）／asteria（gid 400）を使い、オレンジ＋【要確認】にする。
  ユーザ作成そのものは「ユーザ・グループ」シートの範囲なので本書では前提条件に書き、作成コマンドは書かない。
- シリアル No.：LAS-ST-1234-567-9876。ユーザーサイトでのライセンスキー取得に使う値として「パラメータ一覧」に記載する。
  - InstallGuide のインストーラーおよび初期設定画面には、シリアル No. を入力する箇所の記載がない（入力するのはユーザーサイトのアカウント情報とライセンスキー）。
    入力箇所が資料で確認できない場合は推測で手順を作らず、【要確認】にする。
  - 値が見本形式（1234-567-9876）に見えるため、正式な値かどうかも【要確認】にする。
- ライセンスキー、ユーザーサイトのアカウント、スーパーユーザー（/asu）と作業用ユーザーのパスワード、プロキシ認証情報は実値を書かず「＜別途管理＞」とする。

- 次の値は資料に確定値がないため、仮の値（オレンジ＋【要確認】）で記載する。
  - インストールフォルダー：/home/eaiadm/asteriawarp（現行踏襲。InstallGuide のデフォルトは /home/user/asteria5）
  - データフォルダー：ディスク構成最新版に ASTERIA 用の領域があればそれに合わせ、なければ現行踏襲の /disk1/asteria/asteriahome
  - ポート番号のベース：20000（管理コンソール 28080、fsctrl 29899）
  - 作業用ユーザー（フローサービス上のユーザー）：権限・名前は【要確認】

# 作業内容
1. InstallGuide.pdf の該当章を全文読み、Linux（コンソール対話式）の手順を漏れなく抽出する。ページ番号・手順番号を控える。
2. 更新元（ver1）の構成と書式（基本情報／作業概要／パラメータ一覧／作業手順／作業完了確認）を踏襲し、【要確認】の雛形部分を実際の手順に置き換える。
3. 手順は「事前確認 → 作業 → 事後確認 → 切り戻し」の順に作る。
   - 事前確認：OS バージョン、Java（64bit・1.8）のバージョン、実行ユーザ・グループの存在、インストール先の親ディレクトリと空き容量、
     日本語フォントの有無（InstallGuide 1.6.5）、媒体の存在・サイズ、旧バージョンの不存在、使用予定ポート（n8080、n9899 等）が未使用であること
   - 作業：媒体のコピーと実行権限付与 → 実行ユーザへ切替（su - <ユーザ>）→ PATH に Java を追加 → ./install-asteriawarp-linux.bin 実行 →
     インストーラーの各プロンプト（言語＝2 日本語、開始画面、使用許諾＝Y、インストールフォルダー、Java VM の選択、インストール内容の確認）→
     cd <インストールフォルダー> → ./boot/bin/flowsvc → cat boot/log/Bootstrap0.log → ブラウザで http://<サーバ>:28080/index.html の初期設定
     （アカウント情報、ライセンスキー、データフォルダー、ポート番号、/asu パスワード、プロキシ、作業用ユーザー作成）→「完了」
   - 事後確認：./server/bin/fsctrl status（Scheduler が Running）、プロセス（ps）、待ち受けポート（ss -lntp）、管理コンソール http://<サーバ>:28080/ へのログイン、
     fsstop → flowsvc による停止・起動の確認
   - 切り戻し：fsstop → インストールフォルダーの削除 → データフォルダーの削除（InstallGuide 5.1.2）。削除前にパスを確認する行を入れる。
4. 対話式プロンプトは「表示されるプロンプト → 入力する値」を 1 行 1 操作で書き、期待結果には次に表示される画面名を書く。
   コマンドは 1 セルに 1 つ、環境ごとに変わる値は <> で囲む。ブラウザ操作は「【操作】」で始める。
5. パラメータ一覧に次を載せる：製品バージョン、媒体ファイル名・サイズ、媒体配置先、実行ユーザ・グループ、Java のパス、インストールフォルダー、
   データフォルダー、ポート番号のベースと主なポート（管理コンソール、fsctrl）、シリアル No.、ライセンスキー、スーパーユーザー、作業用ユーザー、
   プロキシ、起動・停止コマンド、ログの場所。各行に「確定元」（InstallGuide の章番号など）を書く。
6. 各手順の備考に根拠（例：InstallGuide 2.1.2 手順 4）を書く。ver1 から置き換えた行は「ver1 からの変更点：新規作成（根拠：…）」とする。
7. OS 起動時の自動起動（systemd 化）は InstallGuide に記載がなく「自動起動」シートの範囲なので本書には含めず、備考で参照先を書く。
   必要と判断した追加作業（ファイアウォール、SELinux、サイレントインストール -i silent など）は確定事項として書かず、備考に提案＋【要確認】とする。

- 検証環境：C:\workspace\SystemMigration\docker-compose.yml の ubi8 コンテナ rhel8（ssh -p 2222 root@localhost）。
