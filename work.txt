処理用DB老朽化対応（セキュリティ強化）

# 背景と目的
AP サーバー（RHEL 8.10）の構築手順書を、構築項目ごとに同じ形式で作成していきます。
今回はその土台として、全項目で共通に使う「手順書テンプレート（ひな形）」と、その記入例を 1 つ（CSH）、Excel で作成してください。
手順書は、構築担当者が上から順に実行して結果を記録し、別の担当者がレビューする用途で使います。
そのため「わかりやすい・管理しやすい・操作しやすい・利用しやすい」ことを重視します（具体的な基準は「テンプレートの要件」を参照）。

# 今回の作業範囲
- 作成するもの：テンプレート 1 シートと、CSH の記入例 1 シートの計 2 シートのみ。
- 作成しないもの：CSH 以外の構築項目の手順（後続作業で、テンプレートをコピーして作成します）。
- テンプレートには実際のコマンドや設定値を書かず、記入欄と記入ガイドだけを置きます。
- 記入例シートには、実際のコマンド・設定値・期待結果まで記入します。

# テンプレート（temp シート）の要件
下記を基本構成とします。Web 調査や既存手順書を踏まえて改善した方がよい点があれば変更して構いませんが、変更した場合は完了報告で理由を説明してください。

1. ヘッダ部：プロジェクト名、構築項目名、対象サーバ（ホスト名）、対象 OS、対象ソフトウェアとバージョン、版数、作成日・作成者、更新日・更新者、承認者
2. 改訂履歴：版数、日付、変更内容、変更者
3. 作業概要：目的、前提条件、必要な媒体・ファイル、実行ユーザ、想定所要時間、影響範囲
4. 手順表（1 行 = 1 操作）。列は次のとおり。
   No. / 区分（事前確認・作業・事後確認・切り戻し）/ 作業項目 / 作業内容 / 実行ユーザ / コマンド・操作 / 期待結果 / 実施結果（OK・NG・対象外）/ 実施日時 / 実施者 / 確認者 / 備考
5. 切り戻し手順は、手順表の中で区分「切り戻し」として記載する。

書式の基準
- わかりやすい：各記入欄に「何を書くか」の記入ガイドを薄い文字色で入れる。記入欄と固定欄を背景色で区別する。
- 管理しやすい：手順表ではセル結合を使わない（フィルタ・並べ替え・差分比較ができるようにする）。見出し行にフィルタを設定する。
- 操作しやすい：コマンドは 1 セルに 1 コマンドとし、コピーしてそのまま実行できる形で書く。等幅フォントを使う。環境ごとに変わる値は <ホスト名> のように <> で囲んで統一する。
- 利用しやすい：見出し行でウィンドウ枠を固定する。実施結果は入力規則（プルダウン）にする。A4 横で印刷できるよう列幅と印刷範囲を設定する。

# 記入例（実例_CSH シート）の作成方法
1. 次のファイルの「CSH6.22」シートを読み、手順の内容（何を・どの順で・どう確認するか）を把握する。
   C:\workspace\SystemMigration\AP\APサーバ構築手順書 1 .xlsx
2. その内容を temp シートの型に沿って記入する。レイアウトは既存手順書ではなく temp シートに合わせる。
3. 既存手順は別バージョン（6.22）向けのため、RHEL 8.10 で提供される csh（tcsh パッケージ）のバージョンに置き換える。バージョンとパッケージ名は Red Hat 公式情報で確認すること。
4. バージョンの違いにより既存手順がそのまま使えない箇所（導入方法、パス、設定など）は、黙って書き換えずに備考欄へ「既存手順からの変更点」として記載する。
5. 既存シートにパスワードなどの機密情報が含まれる場合は転記せず、<パスワード> のようなプレースホルダにする。

# 守ってほしいこと
- 参照ファイルや「CSH6.22」シートが見つからない、または読めない場合は、推測で内容を作らず、作業を止めて報告する。
- 確認できなかった値や判断に迷った箇所は、推測で埋めずにセルへ【要確認】と記載する。
- 保存後にファイルを開き直し、シート名・シート数・入力規則・印刷設定が要件どおりか確認する。

  - 起動後のopenssh-server の導入、ホストキー生成(ssh-keygen -A)、
    root パスワードの設定、sshd のフォアグラウンド起動(/usr/sbin/sshd -D)のコマンド集を別途で提供すること。
  - 外部からsshで接続する形で接続する。
- root ログインとパスワード認証は許可する(検証用途)。
- コンテナ名は rhel8、restart は unless-stopped とする。
- 接続確認コマンド(ssh -p 2222 root@localhost)も併せて提示する。
