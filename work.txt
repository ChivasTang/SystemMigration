# 依頼
APサーバの構築手順書のテンプレートを作成し、Excel（.xlsx）形式で ver1 として
C:\workspace\SystemMigration\templates に出力してください。
作成にあたり、Web で構築手順書のテンプレートを調べ、良い点を取り入れてください。


## 1. 背景・目的
- 「処理用DB老朽化対応（セキュリティ強化）」プロジェクトで、AWS 上の RHEL 8.10 に構築する AP サーバ（Apache 2.4、Tomcat 9.0.122 など）の構築手順書を、dev／qa／honban の3環境で同じ書式・同じ品質で作成するための雛形を用意する。
- 今回作成するのはテンプレートのみ。具体的なコマンドや設定値の記入は後続作業とし、枠・見出し・記入ガイドを入れる（記入例を入れる場合は「例」と明記する）。

## 2. 出力
- 形式：Excel（.xlsx）。生成方法は問わない（例：Python の openpyxl）。
- 保存先：C:\workspace\SystemMigration\templates（なければ作成）
- ファイル名：APサーバ構築手順書_テンプレート_ver1.xlsx
- 表紙・改訂履歴のバージョン表記も ver1 に合わせる。同名ファイルが既にある場合は上書きせず、ver2 以降で保存する。
- 生成用スクリプトなどの一時ファイルは、作業フォルダ（C:\workspace\SystemMigration）に残さない。

## 3. 作業前に参照する資料（いずれも C:\workspace\SystemMigration 配下）
1) instructions.txt … プロジェクトの前提とルール。必ず従う。
2) AP\APサーバ構築手順書_od.xlsx … 既存の手順書。シート構成（表紙／更新履歴／インストール一覧／ソフト別の手順シート）と書式の参考にする。このファイルは変更しない。
   - 内容は RHEL 9 系の環境（Amazon Corretto 21 など）のもので、移行後仕様（RHEL 8.10、Corretto 8、Tomcat 9.0.122 など）と異なる。構成と書式の参考にとどめ、バージョンや設定値は転記しない。矛盾点は報告する。
   - RHEL 8.10 と RHEL 9 では標準パッケージや設定方法が異なる。RHEL 8.10 の公式ドキュメントで確認し、確認できない内容は「要確認」とする。
   - 実パスワード、社内ホスト名、プロキシ URL などは転記しない（機密情報は「＜別途管理＞」とする）。
3) docker-compose.yml … 手順の事前検証用ローカル RHEL 8.10 コンテナ（UBI）。EC2 実機とは差異があるため、手順シートで「ローカル検証」と実機の結果を区別できるようにする。

## 4. Web調査（良い点の取り込み）
- 「サーバ構築手順書 テンプレート」「インフラ 構築手順書 Excel」「Linux サーバ構築 手順書 サンプル」「server build runbook template」などで検索し、公式ドキュメントや実績のある技術サイトを優先して3〜5件を選ぶ。
- 次の観点で良い点を抽出し、取り入れる。
  ・構成の網羅性（目的、前提条件、体制、事前準備、手順、確認、切り戻し、エビデンス、課題管理）
  ・手順表の書式（手順No、作業内容、実行ユーザ、コマンド、期待結果、実行結果、判定、実施者・日時）
  ・環境差分のパラメータ化、チェックリスト、承認欄
  ・見やすさ（色分け、凡例、印刷設定）、安全性（変更前バックアップ、切り戻し、危険コマンドの注意喚起）
- 著作権に配慮する。文面やレイアウトをそのまま複製せず、構成や考え方を参考に独自に作成する。利用条件を確認し、再配布不可のものは構成の参考にとどめる。
- 参照した URL、取り入れた点、取り入れなかった点（理由付き）を、「参考資料」シートと完了報告に記載する。
- Web検索が使えない場合は、その旨を報告し、既存資料と一般知識で作成する。一般知識による項目は推測として扱い、要確認にする。

## 5. シート構成
1) 表紙：タイトル、バージョン、作成日、更新日、作成者、PM承認、承認日
2) 改訂履歴：バージョン／更新内容／作成者／作成日／確認者／確認日（初回行に ver1・新規作成を記入）
3) 目次：No／シート名／内容／実施状況／備考（各シートへのハイパーリンク付き）
4) 凡例：色の意味（黄＝現行との差分、オレンジ＝仮の値・要確認）、記号、プレースホルダー表記（＜別途管理＞ など）
5) 概要・前提条件：目的、対象範囲、対象サーバ、体制、必要権限、事前準備物（媒体・RPM・war など）、注意事項、用語
6) パラメータシート：項目／現行値／移行後の値（dev・qa・honban）／備考。区分は AWS（EC2、EBS、セキュリティグループ、IAM など）、OS、ミドルウェア
7) 手順シート雛形（「6. 手順シートの共通レイアウト」参照）
8) 章別の手順シート（雛形に章名と想定項目を設定）
9) 作業チェックリスト（事前・事後）
10) 要確認事項一覧：No／区分（要確認・仮の値）／該当シート・箇所／内容／仮の値／確認先／回答／状況
11) 参考資料：URL／取り入れた点／取り入れなかった点（理由）／利用条件
※ 1〜4・10 はプロジェクトルール上必須。その他は調査結果を踏まえて調整してよい。

章別シートの叩き台（章立てと想定項目は仮置きとして、要確認事項一覧に1件にまとめて登録する）
01 OS基本設定 / 02 セキュリティ設定（不要機能の無効化を含む） / 03 Java（Amazon Corretto 8） / 04 Apache HTTP Server 2.4（mod_proxy_http で Tomcat と連携） / 05 Tomcat 9.0.122 共通（標準アプリ削除、Shutdown ポート・AJP・JMX の無効化） / 06 Tomcat インスタンス別（ap01〜ap06。DB 接続設定の要否は要確認） / 07 ASTERIA Warp 2406（本書の対象に含めるか要確認） / 08 自動起動設定（systemd） / 09 動作確認 / 10 切り戻し

## 6. 手順シートの共通レイアウト
- 上部：手順タイトル、目的、対象サーバ、実施環境（ローカル検証／dev／qa／honban）、実施日、実施者、確認者、前提条件
- 手順表の列：手順No／区分（事前確認・変更前バックアップ・作業・事後確認・切り戻し）／作業内容／実行ユーザ／コマンド・操作／期待結果／実行結果（エビデンス貼付）／判定／実施者／実施日時／備考
- コマンド欄はプロンプト記号を含めず、コピーしてそのまま実行できる形で、省略せずに記載する欄とする。設定ファイルは変更前・変更後を省略せずに記載する欄を設ける。
- 環境ごとに異なる値は手順内に直書きせず、パラメータシートの項目を参照する形にする。

## 7. Excel の品質条件
- すべて日本語。シート名は31文字以内。フォントを統一し、列幅・折り返し・罫線・ヘッダ行の固定を整える。
- 印刷設定：A4 横、1 ページ幅に収める、ヘッダ行を繰り返す、フッターにファイル名とページ番号。
- 入力規則：判定（OK／NG／－）、実施環境、実施状況をプルダウンにする。
- 未記入欄は「＜記入＞」と表示する。
- 作成後にファイルを開き直し、シート一覧、ハイパーリンク、入力規則、印刷設定を確認する。誤字脱字、バージョン表記、改訂履歴、凡例も自己チェックする。

## 8. 進め方・報告
- 上記の構成から変更したい点がある場合のみ、作成前に提案して了承を得る。なければそのまま作成する。
- 範囲は「テンプレート ver1 の作成」のみ。既存ファイルの修正や具体的手順の記入は行わない。範囲外の改善案は成果物に反映せず、提案として報告する。
- 用語・名称（ap01〜ap06、dev／qa／honban など）は instructions.txt に合わせて統一する。
- 不明点は番号を付けてまとめ、選択肢を添えて質問する。
- 完了時は、①作成ファイル名とバージョン、②変更点の要約（Web調査で取り入れた点を含む）、③要確認事項と仮の値の一覧、の3点を簡潔に報告する。
